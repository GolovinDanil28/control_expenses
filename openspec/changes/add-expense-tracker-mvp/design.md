# Design: add-expense-tracker-mvp

## Принцип, из которого вытекает всё остальное

**ИИ не считает деньги.** LLM участвует только на входе (текст → структура) и,
опционально, на выходе (цифры → человеческая формулировка). Остаток, дневная
норма, проценты и итоги считает Python на `Decimal`. Это требование, а не
пожелание: иначе сценарии спецификации unverifiable, а ошибка модели превращается
в ошибку в деньгах пользователя.

## Слои

```
interfaces/  bot/ (aiogram 3)      — разбор апдейтов, форматирование текста, кнопки
application/ use cases              — один сценарий спецификации = один use case
domain/      entities, money, rules — без I/O, без фреймворков
infrastructure/ db (sqlite3), llm (httpx), clock, scheduler
```

Порты (`Protocol` в `application/`): `ExpenseRepository`, `CategoryRepository`,
`CommitmentRepository`, `BudgetRepository`, `AllowlistRepository`,
`NotificationLog`, `PendingInputStore`, `Clock`, `MessageSender`, `IntentParser`.
В тестах — фейки; `Clock` позволяет эмулировать любой момент времени и таймзону.

## Деньги

- В БД — целые **копейки** (`INTEGER`), в домене — `Money` (обёртка над `Decimal`).
  `float` запрещён (`project.md`).
- Парсер принимает `250`, `250р`, `250.50`, `1 250`, `1250руб` → нормализует в копейки.
- Дневная норма округляется **вниз** до копейки: лучше разрешить потратить на копейку
  меньше, чем пообещать невозможное.

## Модель данных (SQLite)

| Таблица | Назначение | Ключевое |
| --- | --- | --- |
| `settings` | key/value: лимит по умолчанию, таймзона, день и час сводки, границы тихого часа | `key PK` |
| `chat_allowlist` | допущенные чаты; `label` — то самое «кто», в отчёты не попадает | `chat_id PK` |
| `category` | справочник трат | `name UNIQUE` |
| `monthly_budget` | лимит на конкретный месяц | `period UNIQUE` (`YYYY-MM`) |
| `expense` | трата | `amount_kopecks`, `spent_on`, `source`, `commitment_id NULL` |
| `commitment` | обязательный платёж | `kind` = `fixed` / `variable`, `day_of_month` |
| `commitment_occurrence` | экземпляр платежа в месяце | `UNIQUE(commitment_id, period)` |
| `pending_input` | ожидающий ответа слот (карточка, ввод суммы коммуналки) | `chat_id PK` |
| `notification_log` | дедупликация оповещений | `dedup_key UNIQUE` |

Заметки:

- `commitment_occurrence` создаётся **лениво и идемпотентно** при первом обращении
  к периоду: не нужен фоновый «генератор месяцев», состояние восстанавливается в
  любой момент. Статусы: `pending` → `paid` / `skipped`.
- `pending_input` (в плане — `input_slot`) нужен, чтобы карточка подтверждения и
  ожидание суммы за коммуналку **переживали рестарт процесса**. FSM aiogram в
  памяти для этого не годится: бот будет перезапускаться Jenkins'ом.
- `notification_log.dedup_key` = `<вид>:<chat_id>:<период>`, например
  `overbudget:123:2026-10`. Повторный алерт о том же превышении невозможен на уровне
  уникального индекса, а не по памяти процесса.

## Формулы

```
committed(p) = Σ сумм обязательств периода p в статусе pending
               (fixed — известная сумма; variable — последняя фактическая сумма
                этого обязательства, если её не было — 0 с пометкой «оценка грубая»)
remaining(p) = budget(p) − committed(p) − spent(p)
days_left    = дней от сегодня до конца месяца, включая сегодня
daily        = floor(remaining / days_left)          # копейки, вниз
```

`budget(p)` — явный лимит месяца, иначе дефолт из `settings`.
`daily < 0` трактуется как «лимит исчерпан», в тексте — сумма перебора.

## Разбор текста

Конвейер из двух стадий, дорогая вызывается только при необходимости:

1. **Детерминированный парсер** (regex + словарь синонимов категорий). Если
   уверенно нашёл сумму и категорию — сразу карточка, LLM не зовём.
2. **`OllamaParser` / `OpenAiParser`** за одним портом `IntentParser`. Возвращает
   strict-JSON: `kind`, `amount`, `category`, `date`. Ответ проходит **валидацию**:
   сумма ≥ 0 и в пределах разумного, категория есть в справочнике (иначе `None`),
   дата парсится. Невалидный ответ = «не понял», бот спрашивает.

В промпт уходят: текст сообщения, названия категорий, сегодняшняя дата и
таймзона. **Агрегаты бюджета и история трат в LLM не отправляются** — приватность
и отсутствие повода для галлюцинаций в цифрах.

## Планировщик

Свой цикл на `asyncio` (тикает раз в минуту, сверяет локальное время с
расписанием), не `APScheduler`: меньше магии, тривиально тестируется через
`Clock`-фейк, поведение при пропуске тика (уснувший ноут) предсказуемо —
каждое оповещение идемпотентно по `dedup_key`, поэтому «догонит» один раз.

- **Недельная сводка** — `WEEKLY_REPORT_DOW`/`WEEKLY_REPORT_TIME` (дефолт пн 11:00).
- **День обязательства** — в рабочее время дня списания.
- **Превышение лимита** — сразу после записи траты, если `remaining < 0`.
- **Тихий час** (`QUIET_START`/`QUIET_END`, дефолт 23:00–08:00): неактивные
  оповещения не отправляются, а переносятся на ближайшее разрешённое время.
  Превышение лимита — тоже переносится: 23:30 сообщать о долгах вредно.

## Конфигурация

`.env`: `BOT_TOKEN`, `ALLOWED_CHAT_IDS`, `DB_PATH`, `TZ`, `MONTHLY_BUDGET_KOPECKS`,
`WEEKLY_REPORT_DOW`, `WEEKLY_REPORT_TIME`, `QUIET_START`, `QUIET_END`,
`LLM_BACKEND` (`none|ollama|openai`), `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`.
Секреты только из окружения, в git не попадают (`.gitignore`, `.env.example`).

## Решения по окружению

- **Python 3.14.5** в `venv`, `uv` и `openspec` на машине нет → команды через
  `venv/bin/...`, спека оформляется вручную по формату `AGENTS.md`, валидатор
  запускается пользователем при появлении CLI.
- **SQLAlchemy/Alembic отложены.** На 3.14 это нативная greenlet-зависимость; для
  девяти таблиц хватает `sqlite3` + версионируемый `schema.sql` с таблицей
  `schema_version`. Переход на ORM — отдельный change, если таблицы вырастут.

## Риски

| Риск | Как снижаем |
| --- | --- |
| ИИ придумал сумму | карточка подтверждения: без тапа `✅` запись не создаётся |
| Дубликаты оповещений после рестарта | `notification_log` с уникальным `dedup_key` в БД |
| Пропущенный тик (машина спала) | идемпотентность + догон при следующем тике |
| Нет связи с Ollama | деградация на regex-парсер, бот просит «сумму и категорию» |
| Ошибка округления денег | копейки в БД, `Decimal` в домене, округление вниз, тесты на границы |
| Утечка данных в LLM | в промпт — только текущее сообщение и справочник категорий |
