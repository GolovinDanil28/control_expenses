# bot-access

## Purpose

Границы доступа к боту: приватный режим, допуск по списку чатов, идентификация
владельца. Определяет, кто вообще может видеть финансовые данные.

## ADDED Requirements

### Requirement: Доступ только из допущенных чатов
Система SHALL обрабатывать сообщения и командные нажатия только из чатов,
идентификатор которых входит в настроенный список допуска; сообщения из всех
остальных чатов SHALL игнорироваться без объяснений их содержимого.

#### Scenario: Сообщение из допущенного чата
- **WHEN** сообщение приходит из чата, идентификатор которого есть в списке допуска
- **THEN** система обрабатывает сообщение обычным для его типа образом

#### Scenario: Сообщение из недопущенного чата
- **WHEN** сообщение приходит из чата, идентификатора которого нет в списке допуска
- **THEN** система не выполняет никаких операций записи
- **AND** не отправляет в этот чат никакого ответа

#### Scenario: Нажатие на inline-кнопку в недопущенном чате
- **WHEN** callback-запрос приходит из чата, отсутствующего в списке допуска
- **THEN** система не изменяет состояние данных
- **AND** завершает callback без видимого результата для пользователя

### Requirement: Первый в списке допуска чат становится владельцем
Система SHALL считать владельца чатом, указанным в списке допуска первым, и
SHALL отправлять в него инициативные оповещения (сводки, напоминания, алерты),
даже если владелец ни разу не написал боту.

#### Scenario: Оповещение уходит владельцу
- **WHEN** планировщик решает отправить недельную сводку
- **THEN** сводка доставляется в чат владельца

#### Scenario: Пустой список допуска
- **WHEN** процесс запускается с пустым или незаданным списком допуска
- **THEN** система отказывается запускаться
- **AND** в журнал попадает сообщение о причине отказа

### Requirement: Оповещение о неизвестном чате владельцу
Система SHALL один раз на чат уведомить владельца о попытке обращения из чата,
отсутствующего в списке допуска, без раскрытия текста этого сообщения.

#### Scenario: Неизвестный чат написал боту
- **WHEN** сообщение приходит из чата, отсутствующего в списке допуска
- **AND** ранее владелец о этом чате не уведомлялся
- **THEN** владелец получает уведомление с идентификатором чата
- **AND** текст исходного сообщения в уведомлении отсутствует

#### Scenario: Повторная попытка из того же чата
- **WHEN** следующее сообщение приходит из того же недопущенного чата
- **THEN** повторное уведомление владельцу не отправляется

### Requirement: Идентификация автора траты без вывода в отчёты
Система SHALL сохранять идентификатор чата-источника для каждой траты и SHALL НЕ
выводить его ни в одном пользовательском отчёте или сводке.

#### Scenario: Трата сохранена с источником
- **WHEN** пользователь подтверждает трату в чате с идентификатором X
- **THEN** сохранённая трата содержит источник X

#### Scenario: Источник не виден в отчёте
- **WHEN** пользователь запрашивает отчёт за период, содержащий траты из разных допущенных чатов
- **THEN** в ответе отсутствуют идентификаторы чатов и имена авторов

### Requirement: Секреты не покидают процесс
Система SHALL получать токен бота и ключи доступа к моделям только из переменных
окружения и SHALL НЕ записывать их в хранилище данных, в журнал или в текст
любого сообщения.

#### Scenario: Токен не попадает в журнал
- **WHEN** система логирует запуск или ошибку подключения
- **THEN** значение токена в журнале отсутствует
