# Change: Приватный Telegram-бот учёта расходов (MVP)

## Why

Учёт трат в таблицах и банковских приложениях не отвечает на главный вопрос:
**«сколько мне можно тратить до конца месяца, учитывая обязательные платежи?»**
Банк показывает историю, но не знает про квартиру, счётчики и подписки, которые
съедят часть бюджета в ближайшие дни.

Нужен личный бот в Telegram, который:

1. принимает трату одним сообщением («купил кофе 250») без заполнения форм;
2. сам считает деньги и остаток — человек ничего не пересчитывает;
3. помнит про обязательные платежи и передачу показаний счётчиков;
4. раз в неделю присылает сводку и мгновенно предупреждает о превышении бюджета.

Продукт приватный: один владелец, доступ по allowlist идентификаторов чатов,
локальное хранилище, никаких сторонних облаков и аналитик.

## What Changes

- **Ввод траты текстом с подтверждением.** Сообщение разбирается на
  «сумма + категория + дата», показывается карточка предпросмотра с inline-кнопками
  (подтвердить / сменить категорию / исправить сумму / отменить). В базу попадает
  только подтверждённая запись.
- **Месячный бюджет: один общий лимит.** Никаких лимитов по категориям.
  Ключевая метрика — **дневная норма**: `(лимит − обязательства месяца − потрачено) / дни до конца месяца`.
- **Обязательства (commitments).** Два вида: с фиксированной суммой и датой
  (квартира, связь, подписки) и с плавающей суммой (коммунальные). Для плавающих —
  ритуал: напоминание → пользователь вводит фактическую сумму → появляется трата.
- **Отчёт по запросу и раз в неделю.** Категории, суммы, план/факт, дневная норма,
  ближайшие обязательства.
- **Оповещения.** Мгновенно — только два события: превышение лимита и день списания
  обязательства. Всё остальное копится к недельной сводке. Уважается «тихий час».
- **ИИ как разборчик текста, а не как калькулятор.** LLM (пока локальный Ollama,
  далее — OpenAI-совместимый API по ключу) переводит свободный текст в структуру
  траты. Все денежные расчёты выполняет детерминированный код. Без настроенного
  ИИ бот полностью работоспособен на шаблонном разборе.

## Capabilities

| Capability | Граница |
| --- | --- |
| `bot-access` | допуск по allowlist чатов, приватность, поле «кто» в модели без вывода |
| `expenses` | фиксация, правка и удаление трат, категории, период |
| `budgets` | месячный лимит, остаток, дневная норма, превышение |
| `commitments` | обязательные платежи, их состояния, проведение оплаты |
| `reminders` | расписание оповещений, мгновенные события, тихий час |
| `reports` | отчёт по периоду и недельная сводка |
| `ai-insights` | разбор свободного текста, деградация без ИИ |

## Out of scope (следующие change'и)

- Доходы, несколько счетов, переносы между кошельками, валюты кроме ₽.
- Лимиты по отдельным категориям и подбюджеты.
- Загрузка выписок из банка (CSV/OFX), автоплатежи, push-уведомления вне Telegram.
- Веб-интерфейс, мобильные виджеты, мультиязычность.
- Экспорт в CSV/XLSX и бэкап в облако.
- Несколько владельцев с раздельной статистикой («кто потратил»).

## Impact

- **Модель данных:** новая SQLite-БД (траты, категории, обязательства, лимиты,
  допуск чатов, журнал оповещений, ожидающий ввод).
- **Зависимости:** `aiogram` (Telegram), `httpx` (LLM-адаптер), `pytest-asyncio`.
  ORM не вводится — стандартный `sqlite3`, чтобы не тянуть нативные зависимости.
- **Runtime:** один долгоживущий процесс (long polling + планировщик),
  `docker-compose.yml` для запуска; далее — сборка в Jenkins на отдельной машине.
- **Конфигурация `openspec/project.md`:** интерфейсом продукта становится Telegram
  вместо CLI/веба; ограничение «никаких обязательных внешних сервисов» уточняется —
  ИИ остаётся опциональным адаптером, при его отсутствии все сценарии работают.
- **Риски:** см. `design.md` → «Риски».
