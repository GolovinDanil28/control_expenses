# control-expenses

Приватный Telegram-бот учёта личных расходов.

Трату вводят текстом («купил кофе 250») — бот показывает карточку подтверждения,
где сумму и категорию можно поправить или отменить, и только после подтверждения
записывает. Один общий месячный лимит; дневная норма считается как
`(лимит − обязательства − потрачено) ÷ дни до конца месяца` с округлением вниз.
Раз в неделю приходит сводка, отдельно — алерт о превышении лимита и напоминание
в день обязательного платежа.

**ИИ не считает деньги.** Модель только разбирает текст в структуру; все суммы,
остатки и нормы считает Python на `Decimal`, в базе суммы хранятся в копейках.

## Стек

- Python 3.12+ (venv в репозитории: `venv/`)
- [aiogram 3](https://docs.aiogram.dev/) — Telegram-бот, long polling
- SQLite из stdlib (`sqlite3`) + версионируемый `schema.sql`
- `httpx` — клиент к Ollama / OpenAI-совместимому API (опционально)
- `pytest`, `ruff`, `mypy --strict`

```bash
python3 -m venv venv
```

## Переменные окружения

Все настройки читаются из `.env` (шаблон — `.env.example`, сам `.env` в git не попадает).

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `BOT_TOKEN` | Токен бота от @BotFather | — (обязательно) |
| `ALLOWED_CHAT_IDS` | Допущенные chat_id через запятую | — (обязательно) |
| `DB_PATH` | Путь к файлу SQLite | `data/control_expenses.db` |
| `TZ` | Таймзона (IANA) | `Europe/Moscow` |
| `MONTHLY_BUDGET_KOPECKS` | Лимит месяца по умолчанию, в копейках; пусто — лимит не задан | не задан |
| `BUDGET_THRESHOLD_RATIO` | Доля лимита для однократного предупреждения, `0 < доля ≤ 1` | `0.8` |
| `WEEKLY_REPORT_DOW` | День недельной сводки, 0=пн | `0` |
| `WEEKLY_REPORT_TIME` | Время недельной сводки, `HH:MM` | `11:00` |
| `QUIET_START` / `QUIET_END` | Тихий час: оповещения переносятся, а не отбрасываются | `23:00` / `08:00` |
| `LLM_BACKEND` | `none` \| `ollama` \| `openai` | `none` |
| `LLM_BASE_URL` | Адрес модели | `http://localhost:11434` |
| `LLM_MODEL` | Имя модели | `qwen2.5:3b` |
| `LLM_API_KEY` | Ключ для OpenAI-совместимого API | пусто |
| `LLM_TIMEOUT_SECONDS` | Таймаут запроса к модели | `10` |

При `LLM_BACKEND=none` работает детерминированный парсер: сумма и категория из
текста вида «кофе 250», «250р», «1 250».

## Статус

Реализован **сквозной срез**: ввод траты текстом → карточка предпросмотра →
подтверждение → запись в SQLite, включая правку суммы/категории, `/addcategory`,
`/undo` и `/edit` последней траты. Черновик карточки хранится в БД и переживает
перезапуск процесса.

Готовы слои `domain` и `infrastructure/parsing` (детерминированный разбор без ИИ)
с тестами. Также работает capability **`budgets`**: `/budget <сумма> [ГГГГ-ММ]`
задаёт лимит месяца, `/budget` без аргументов показывает план, потраченное,
остаток и дневную норму; достижение порога и превышение фиксируются однократно за
месяц и переживают рестарт.

Также работает capability **`commitments`**: `/addbill` заводит обязательство
(фиксированное, `var` — плавающее, `meter` — показания счётчиков), `/bills` —
список с кнопками «Оплатить»/«Пропустить», `/pay` и `/skip` — то же по номеру,
`/delbill` удаляет обязательство, не трогая прежние траты. Неоплаченные
обязательства уменьшают остаток месяца, плавающие оцениваются по прошлой
фактической сумме (остаток помечается как оценка). Экземпляры платежей месяца
создаются лениво и идемпотентно.

Также работает capability **`reports`**: `/report 01.10 07.10` — итоги по
категориям и сравнение с предыдущим равным периодом, `/report` без аргументов —
месяц с планом, остатком и дневной нормой. Здесь же формируется недельная сводка —
её доставкой по расписанию занимается `reminders`.

Также работают **`reminders`** и планировщик: напоминания об обязательствах в день
платежа (с кнопками «Оплатить»/«Пропустить»), алерт о превышении лимита и
недельная сводка по расписанию (`/schedule <день 0–6> <ЧЧ:ММ>`). Оповещения
уважают «тихий час» — переносятся, а не теряются — и дедуплицируются по ключу в
БД, поэтому перезапуск и два экземпляра процесса не приводят к дублям.

Наконец, работает capability **`ai-insights`**: при `LLM_BACKEND=ollama` или
`openai` свободный текст разбирает модель (strict-JSON с валидацией ответа), а
детерминированный разбор остаётся первым звеном и страховкой — при `none` или
недоступном бэкенде бот просто продолжает работать. В промпт уходят только текст
сообщения, категории и дата.

Проверено на живой Ollama (`qwen2.5-coder:7b`): «купил кофе 250» → 250 ₽ · Еда,
«обед 400, такси 300» → 400 ₽ с пометкой про остальные траты, «потратил немного на
обед» → отказ с причиной «нет суммы».

[`openspec/changes/add-expense-tracker-mvp/tasks.md`](openspec/changes/add-expense-tracker-mvp/tasks.md);
принятые решения — в `design.md` того же change.
